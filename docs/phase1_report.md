# 第一阶段报告：TN5000 环境与数据检查

## 1. 研究问题与阶段边界

本项目要回答的问题是：在 TN5000 的良恶性分类任务上，向模型提供“整图＋人工标注 ROI”，相比只提供整图，是否带来可重复的性能收益。计划主模型为 `Qwen/Qwen3-VL-4B-Instruct`。

第一阶段只检查运行环境、公开数据、标签、框、划分和预览。没有下载大模型，没有训练或推理，也没有进行强化学习或界面开发。因此，本报告不能回答 ROI 是否提高模型性能。

## 5. TN5000 实际目录结构

本轮数据来自官方 Figshare 发布。正式数据位于本机的 `data/official/TN5000_forReview/`，但该目录被 Git 忽略：

```text
TN5000_forReview/
├── Annotations/             # 5,000 份 <image_id>.xml
├── JPEGImages/              # 5,000 张 <image_id>.jpg
└── ImageSets/Main/
    ├── train.txt            # 3,500 个图像 ID
    ├── val.txt              # 500 个图像 ID
    ├── test.txt             # 1,000 个图像 ID
    └── trainval.txt         # train ∪ val，共 4,000 个 ID
```

原始图像均为 RGB JPEG，但并非统一尺寸。实测有 9 种尺寸，其中 3,975 张为 718×500。数据目录中还发现两个不属于官方 ZIP 的 `.ipynb_checkpoints` 文件；它们没有计入正式 5,000 例统计，也没有被删除。

## 6. 标签与框的实际格式及依据

官方论文的 Data Records 段落明确说明：

- XML 的 `<object><name>` 是类别标签；`0` 表示良性，`1` 表示恶性。
- 框位于 `<bndbox>`，顺序为 `xmin, ymin, xmax, ymax`。
- JPEG 与 XML 通过相同文件名对应。

依据是论文 [TN5000: An Ultrasound Image Dataset for Thyroid Nodule Detection and Classification](https://www.nature.com/articles/s41597-025-05757-4) 和固定提交 `ddc1ab40ce9fd8b8d7f7c7df920897686822b4c6` 中的官方加载代码。

公开加载器先执行 `int(float(value))`，再对四个坐标全部减 1。本轮 ROI 使用减 1 后的四个值作为 Pillow 半开区间，不加边、不缩放、不夹紧。5,000 个加载结果已与官方解析方法逐例核对。这个结论证明本轮裁剪与公开加载代码一致，不能证明标注者对右下端点的原始像素语义另有独立说明。

每张正式图像恰有一个 `<object>`，所以本发布版本可以把该对象的类别用作图像级监督标签。脚本没有根据图像外观或类别数量猜测标签，也不会在多对象时自动挑最大框。

## 7. 数量、类别与质量检查结果

### 7.1 数据与类别

| 划分 | 图像数 | 良性 `0` | 恶性 `1` |
|---|---:|---:|---:|
| train | 3,500 | 1,032 | 2,468 |
| val | 500 | 125 | 375 |
| test | 1,000 | 269 | 731 |
| 合计 | 5,000 | 1,426 | 3,574 |

论文正文汇总为良性 1,428、恶性 3,572，与发布 XML 实测相差 2 例。只能确认汇总不一致，不能从总数判断哪两个 XML 应该改成什么，因此没有修改标签。

### 7.2 完整性和框检查

| 检查项 | 状态 | 实测结果 |
|---|---|---|
| 缺失 JPEG | 通过 | 0 |
| 缺失 XML | 通过 | 0 |
| 无 `<object>` | 通过 | 0 |
| 损坏或无法解码图片 | 通过 | 0 |
| 未知类别 | 通过 | 0 |
| 非整数、非数值、非正面积框 | 通过 | 0 |
| 官方转换后越界框 | 通过 | 0 |
| XML 尺寸与 JPG 不一致 | 发现问题 | 2 例：`002589`、`004092` |
| 原始坐标超过图像边界 | 发现问题 | 1 例：`003813` 的原始 `xmax=719`，图宽 718 |

`003813` 经官方四坐标减 1 后成为 `[332,72,718,350]`，可以作为宽 718 图像的半开右边界。本报告仍将原始坐标记为疑点，没有自动修复。

### 7.3 重复图像

文件 SHA256 和解码后 RGB 像素 SHA256 得到相同结果：

- 119 个精确重复组；
- 涉及 245 个图像 ID，即相对唯一图像多出 126 份；
- 65 个重复组跨官方划分；
- 跨划分分布为 train–val 23 组、train–test 39 组、val–test 3 组；
- 重复组内没有发现类别冲突。

这证明官方 ID 划分互不重叠，但图像内容并非互不重叠。未经处理直接使用官方 split 会产生图像级泄漏风险。完整分组见 [重复图像分组](../reports/duplicate_groups.md)。本轮只检查完全相同的编码文件和解码像素，没有运行感知哈希、特征相似度或多视角患者匹配，所以不能声称已排除近重复。

## 8. 官方划分、患者 ID 和结节 ID

官方 `train`、`val`、`test` 的图像 ID 数量和 7:1:2 比例正确，三个 ID 集合没有交集，`trainval` 等于 `train ∪ val`。论文和 Figshare 元数据均称它是图像级随机划分。

发布的 XML、文件名和 split 文件中没有独立的患者 ID、结节 ID 或映射表。六位编号只能当作图像 ID。因此：

- 官方图像 ID 划分已验证；
- 患者级独立目前没有足够信息确认；
- 结节级独立目前没有足够信息确认；
- 精确图像去重不能替代患者级或结节级隔离。

## 9. ROI 预览

脚本把结构有效的 ID 排序后，使用 `random.Random(20260923).sample(..., 20)` 无放回抽样，成功生成 20 组：原始整图、叠框整图、无 padding 的 ROI 以及三栏审计面板。另生成 4 张联系表，每张含 5 例。

独立复核确认：20 个 ROI 与源图相同坐标的 NumPy 切片逐像素一致；随机选择顺序一致；官方加载器坐标与标签解析一致。预览已在 AutoDL 实际生成并目视打开，但用户的医学或标注语义验收仍未完成。

这些预览含 TN5000 图像内容，当前被 `.gitignore` 排除。待确认数据集许可后再决定是否单独发布。审计面板底部含真实标签，只能用于检查，不能作为模型输入或推理提示。

预览解释见 [预览与统计图说明](preview_guide.md)。

## 10. 已发现的问题

1. 官方 split 中有 65 组完全相同的图像跨集合，正式实验前必须制定处理协议。
2. 发布 XML 类别总数与论文汇总不一致，不能靠猜测修正。
3. `002589` 和 `004092` 的 XML 图像尺寸字段与实际 JPEG 不一致。
4. `003813` 的原始右边界超过图宽 1 像素，但官方转换后的半开边界可用。
5. 没有患者 ID 或结节 ID，无法验证患者级或结节级隔离。
6. 92 例框的宽或高小于 32 像素；官方一个数据配置含 `bbox_min_size=32`，若以后复用该配置可能忽略这些目标。
7. 若使用原图和 ROI 双输入，原图中的测量十字标记可能成为混杂因素，本阶段没有做全库标记分析。

## 11. 尚未验证的内容

- Qwen3-VL 的安装、输入模板、显存、量化、推理、微调和训练稳定性；
- 完整 MMDetection 运行环境和论文基准配置的可复现性；
- 感知近重复、多视角同患者或同结节泄漏；
- 标注的临床正确性；
- 人工 ROI 是否改善分类性能；
- 用户对 20 个预览的最终验收。

目前不存在“代码已经写好但尚未运行”的模型训练流水线。第一阶段的四个 Python 脚本都曾在 AutoDL 实际成功运行；本次 GitHub 整理只做语法检查，不重新执行耗时数据任务。

## 12. 下一阶段建议

1. 先完成用户对 20 个 ROI 的目视验收。
2. 把官方 split 作为可比基线，同时设计一个按精确重复组隔离的派生 split；两个结果分开报告，不改原始文件。
3. 向数据发布方询问患者／结节映射和论文类别计数差异；在没有答复前如实标记信息缺失。
4. 设计严格配对的“整图”与“整图＋人工 ROI”输入，两组使用相同样本、标签、seed、训练步数和评估指标。
5. 真实良恶性标签只用于监督与评估，不进入提示文本。人工 ROI 的实验结论只能表述为“给定人工定位的增益”。
6. 获得确认后再安装 Qwen 依赖，先做单样本输入与显存测试，再开始正式实验。
